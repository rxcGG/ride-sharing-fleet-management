# ADR-0003. Вхід користувачів і контроль доступу

## Статус

Proposed

## Контекст

Пасажири, водії й оператори мають різні права. Треба перевіряти, хто може переглядати дані поїздки.

## Рішення

Для входу обрано OpenID Connect через зовнішнього провайдера. Система окремо перевіряє права на кожну поїздку. Токени не записуються в журнали.

## Розглянуті альтернативи

- **Власні паролі:** більше контролю, але їх треба самостійно захищати.
- **API-ключі:** підходять для зв'язку сервісів, але не для різних ролей користувачів.
- **OpenID Connect:** провайдер підтверджує особу, а система перевіряє права; цей варіант обрано.

## Наслідки

- **Перевага:** системі не потрібно самостійно зберігати паролі.
- **Компроміс:** вхід залежить від зовнішнього провайдера.
