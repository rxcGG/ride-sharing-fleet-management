# ADR-0002. Стратегія зберігання даних

## Статус

Proposed

## Контекст

Системі потрібно зберігати поїздки й шукати водіїв за місцем. Дані про поїздки мають залишатися узгодженими.

## Рішення

Обрано PostgreSQL із PostGIS для основних даних і пошуку за місцем. Redis можна додати як тимчасовий кеш координат водіїв.

## Розглянуті альтернативи

- **MongoDB:** гнучка схема, але складніше узгодити дані поїздки й оплати.
- **PostgreSQL/PostGIS:** зберігає основні дані й підтримує пошук за місцем; цей варіант обрано.

## Наслідки

- **Перевага:** дані поїздок зберігаються разом, а пошук використовує місце водія.
- **Компроміс:** якщо додати Redis, треба стежити за оновленням кешу.
