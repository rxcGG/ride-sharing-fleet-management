# ADR-0001. Стиль архітектури системи

## Статус

Proposed

## Контекст

Потрібно розділити пошук водія, поїздки й тарифи. На початку проєкт невеликий, тому окремі сервіси для кожної частини будуть зайвими.

## Рішення

Для основних функцій обрано модульний моноліт: керування поїздками, тарифами й автопарком залишається в одному застосунку. Пошук водія винесено в окремий сервіс, щоб масштабувати його незалежно; API звертається до нього через gRPC. Сповіщення обробляє окремий фоновий процес через RabbitMQ.
## Розглянуті альтернативи

- **Звичайний моноліт:** простий запуск, але частини можуть змішатися.
- **Мікросервіси:** окреме масштабування, але складніша підтримка.
- **Модульний моноліт:** розділені частини в одному застосунку; обрано для початку.

## Наслідки

Пошук водія можна масштабувати окремо від основного API, а сповіщення обробляються у фоні. Натомість потрібно підтримувати gRPC, RabbitMQ і кілька окремих процесів. Інші функції залишаються в одному застосунку, тому їх простіше розробляти й запускати.
