# Сценарії якісних атрибутів

## QAS-1. Підбір водія під навантаженням

- **Source:** пасажир.
- **Stimulus:** надсилає запит на поїздку.
- **Environment:** пікове навантаження.
- **Artifact:** API поїздок і пошук водія.
- **Response:** система знаходить водія й повідомляє пасажира.
- **Response Measure:** p95 відповіді до 2 с при 500 запитах за секунду; поїздка призначається лише одному водієві.

## QAS-2. Відновлення після повторного запиту

- **Source:** застосунок пасажира.
- **Stimulus:** повторно надсилає запит після затримки мережі.
- **Environment:** сервер міг уже отримати перший запит.
- **Artifact:** API створення поїздки.
- **Response:** система повертає створену поїздку, а не створює дублікат.
- **Response Measure:** немає дублів у 10 000 повторних запитів; відповідь надходить до 3 с після відновлення зв'язку.

## QAS-3. Заборона доступу до чужої поїздки

- **Source:** користувач сервісу.
- **Stimulus:** намагається відкрити чужу поїздку.
- **Environment:** звичайна робота API.
- **Artifact:** API поїздок.
- **Response:** система відхиляє запит і записує спробу в журнал.
- **Response Measure:** відповідь 403 або 404; особисті дані не повертаються.

## QAS-4. Передавання сигналу SOS

- **Source:** пасажир або водій.
- **Stimulus:** натискає кнопку SOS під час поїздки.
- **Environment:** поїздка активна.
- **Artifact:** API безпеки та панель оператора.
- **Response:** система підтверджує сигнал і сповіщає оператора.
- **Response Measure:** 95% сигналів підтверджуються до 5 с і зберігаються в журналі.

## QAS-5. Перевірка зміни правила тарифу

- **Source:** розробник тарифів.
- **Stimulus:** змінює правило розрахунку тарифу.
- **Environment:** звичайне тестове середовище.
- **Artifact:** модуль тарифів.
- **Response:** нове правило можна перевірити окремо від решти системи.
- **Response Measure:** модульні тести покривають не менше 80% основної логіки тарифів.
